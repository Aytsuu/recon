- After invalidating a draft, set the case to `ready_for_draft` only when
  `provider_name`, `problem_summary`, and `desired_outcome` are all non-blank

- When none remain pending, set the case to `ready_for_draft` only if all three

## Scope correction — 2026-09-12

### Finding

The A3 board instructions specify a pre-recorded upload-and-poll adapter:

- Upload bytes → `POST /v2/upload`
- Submit → `POST /v2/transcript`
- Poll → `GET /v2/transcript/{id}` until `completed`
- Expose via `POST /api/cases/{case_id}/transcribe` (multipart audio)

The AssemblyAI documentation consulted during A3 implementation describes the
**realtime streaming STT** API instead:

- Browser opens `wss://streaming.assemblyai.com/v3/ws` with a token
- Client streams audio as binary frames
- Server emits Turn events; `end_of_turn: true` marks a finalized turn
- Client sends `{"type":"Terminate"}` to end the session
- Browser must use a short-lived token (never the permanent key)

These are incompatible interfaces. The committed A3 code (upload/poll) was
produced from the board instructions and is internally consistent with those
instructions. It is not a realtime streaming implementation.

No implementation files were changed. The following documentation was updated
to describe the correct realtime design:

`ExtractionResult` is an immutable value containing:

```text
provider_name:          str | None
service_name:           str | None
issue_category:         str | None
problem_summary:        str | None
attempted_resolutions:  list[str]
desired_outcome:        str | None
```
